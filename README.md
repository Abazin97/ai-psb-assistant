# ПСБ — юридический AI-ассистент

Веб-чат отвечает на вопросы по документам из локальной базы знаний. Фронтенд ведёт диалог, бекенд хранит чаты и сообщения в PostgreSQL, ML-сервис ищет подходящие фрагменты и формирует ответ через внешний LLM API.

## Архитектура

```text
Браузер
  └─ frontend: Nginx — страница, прокси /api/* к backend и /health к ML
       ├─ backend: Go HTTP API — чаты, история, подключение к БД и ML
       │    ├─ postgres: PostgreSQL — чаты, сообщения и миграции схемы
       │    └─ ml: Python HTTP API — поиск по knowledge-base.zip и генерация ответа
       └─ внешний LLM API: OpenRouter
```

Бекенд применяет схему БД при запуске. При отправке вопроса он добавляет недавнюю историю диалога к тексту вопроса и вызывает ML. Вопрос, ответ и снимки использованных фрагментов сохраняются в БД после успешного ответа ML. ML получает `id` и `question`, возвращает `id`, `kind`, `answer` и `sources`. Если локальная проверка релевантности не находит достаточного подтверждения, ML возвращает `kind: "clarification"` и пустой список источников.

## Запуск через Docker Compose

1. Получите API-ключ в [OpenRouter](https://openrouter.ai/settings/keys) и вставьте его в `LLM_API_KEY` в `.env`. Оставьте `LLM_MODEL=openrouter/free`, если хотите использовать бесплатный маршрутизатор моделей.

2. Запустите весь проект одной командой:

   ```bash
   docker compose up --build -d
   ```

Compose собирает сервисы, запускает PostgreSQL, бекенд, ML и фронтенд. Персистентные данные PostgreSQL находятся в Docker volume `postgres_data`.

## Переменные окружения

Репозиторий содержит безопасный шаблон `.env.example`. Файл `.env` исключён из Git.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `LLM_BASE_URL` | `https://openrouter.ai/api/v1` | Базовый URL внешнего LLM API. Для OpenRouter оставьте это значение. |
| `LLM_API_KEY` | пусто | Секретный ключ OpenRouter. Обязателен для реальной генерации; не публикуйте его. |
| `LLM_MODEL` | `deepseek/deepseek-v4.1-flash` в Compose | Имя модели/маршрутизатора OpenRouter. В `.env.example` задано `openrouter/free`. |
| `ML_MOCK` | `false` | `true` включает мок-ответы бекенда вместо вызовов ML. Мок покрывает только несколько демонстрационных сценариев. |
| `USE_EMBEDDINGS` | `true` | Включает векторный поиск. Значение `false` отключает embeddings и оставляет лексический поиск по базе знаний. |
| `USE_RERANKER` | `true` | Включает дополнительное ранжирование фрагментов. Значение `false` отключает этот вызов. |
| `ML_SOURCE_MIN_COSINE` | `0.45` | Минимальная косинусная близость для выдачи источника при включённых embeddings; лексическая проверка и точные ссылки также учитываются. |
| `EMBEDDER_BASE_URL` | пусто | Необязательный URL сервиса embeddings; если пусто, используется `LLM_BASE_URL`. |
| `EMBEDDER_API_KEY` | пусто | Необязательный ключ embeddings; если пусто, используется `LLM_API_KEY`. |
| `RERANKER_BASE_URL` | пусто | Необязательный URL reranker; если пусто, используется `LLM_BASE_URL`. |
| `RERANKER_API_KEY` | пусто | Необязательный ключ reranker; если пусто, используется `LLM_API_KEY`. |
| `ML_URL` | `http://ml:8000` | Внутренний адрес ML для бекенда в сети Compose. Обычно менять не нужно. |
| `ML_REQUEST_BUDGET_SECONDS` | `130` | Максимальное время ML-обработки одного запроса. |
| `ML_MAX_WORKERS` | `4` | Максимум параллельных запросов ML. |
| `FRONTEND_PORT` | `8080` | Порт фронтенда на компьютере разработчика. Открывайте `http://localhost:<значение>`. |

Compose задаёт адрес и учётную запись PostgreSQL для внутренней сети. Значения в `docker-compose.yml` рассчитаны на локальный запуск; для развёртывания в общей или публичной среде их нужно заменить и настроить защищённое хранение секретов.

### Подключение OpenRouter

Используется сервис **OpenRouter**, модель задаётся переменной `LLM_MODEL`, а ключ — `LLM_API_KEY`.

1. Создайте API-ключ в кабинете OpenRouter.
2. Если `.env` ещё нет, скопируйте `.env.example` в `.env`; иначе измените существующий файл.
3. Вставьте ключ только в `LLM_API_KEY`; оставьте `LLM_BASE_URL=https://openrouter.ai/api/v1` и `LLM_MODEL=openrouter/free`.
4. Сохраните файл и запустите Compose командой выше. Если контейнеры уже работают, примените новые значения командой `docker compose up -d --force-recreate ml backend`.

`GET /health` проверяет конфигурацию и готовность ML-процесса.

## Порты и адреса

| Адрес на хосте | Сервис | Назначение |
| --- | --- | --- |
| `http://localhost:8080` | фронтенд | Веб-приложение; порт меняется через `FRONTEND_PORT`. |
| `http://localhost:8080/api/...` | бекенд через Nginx | REST API чатов и проверка состояния бекенда. |
| `http://localhost:8080/health` | ML через Nginx | Проверка ML из браузера или Postman. |
| `http://127.0.0.1:8001/health` | ML напрямую | Прямая проверка ML, минуя фронтенд и бекенд. |
| `http://127.0.0.1:8001/answer` | ML напрямую | `POST` с JSON `{"id":"test-1","question":"Ваш вопрос"}`. |
| `http://127.0.0.1:8001/documents/{doc_id}` | ML напрямую | Скачать документ в формате DOCX. |
| `localhost:5432` | PostgreSQL | Подключение к локальной БД из клиента БД. |
| `backend:8080`, `ml:8000`, `postgres:5432` | внутренняя сеть Compose | Адреса сервисов друг для друга. Бекенд не публикует свой порт на хост. |


## Основные API-маршруты

- `GET /api/health` — состояние БД и ML через бекенд; при деградации возвращает HTTP 503.
- `POST /api/chats` — создать чат.
- `GET /api/chats?limit=50` — список чатов текущего браузера.
- `GET /api/chats/{id}` — чат и его сообщения.
- `POST /api/chats/{id}/messages` — отправить вопрос; тело запроса: `{"text":"..."}`.
- `DELETE /api/chats/{id}` — удалить чат.
- `GET /api/documents/{doc_id}` — скачать документ-источник в DOCX с корректным MIME-типом и именем файла.
- `GET /health` — статус ML, база знаний и наличие настроек LLM.
- `POST /answer` на ML — контракт `{"id":"...","question":"..."}` → `{"id":"...","kind":"answer|clarification","answer":"...","sources":[...]}`. При недостаточной релевантности ML возвращает просьбу уточнить вопрос без источников.
- `GET /documents/{doc_id}` на ML — DOCX из `knowledge-base.zip`: существующий DOCX отдаётся без перекодирования, текстовые форматы преобразуются в DOCX.

## Порядок проверки основного сценария

1. Запустите контейнеры и дождитесь, пока ML закончит загрузку базы знаний:

   ```bash
   docker compose ps
   ```

2. Проверьте `http://localhost:8080/health`. Для настроенного ML ожидаются `mode: "live"` и `llm_configured: true`. HTTP 200 сам по себе не доказывает, что ключ действителен: подтвердите это следующим шагом.
3. Проверьте `http://localhost:8080/api/health`. Ожидаются `status: "ok"`, `db: "ok"` и `ml: "ok"`.
4. Откройте `http://localhost:8080`, отправьте вопрос по документам и дождитесь ответа.
5. Нажмите ссылку источника под ответом: откроется панель материалов. Нажмите имя файла, чтобы раскрыть выдержку, или значок скачивания, чтобы получить DOCX. Обновите страницу и убедитесь, что источники сохранились вместе с сообщением. Для просмотра записей в БД выполните:

   ```bash
   docker compose exec postgres psql -U olp -d postgres -c "SELECT c.id, c.title, m.seq, m.role, m.content FROM chats c JOIN messages m ON m.chat_id = c.id ORDER BY c.updated_at DESC, m.seq;"
   ```


ML может вернуть HTTP 200 на `/health` со значением `status: "degraded"`, если процесс запущен, но `LLM_API_KEY` не задан. В таком состоянии ответ на `/answer` не сформируется. Неуспешный вызов ML не записывает пару вопрос/ответ в БД.

## Зависимости

- Docker и Docker Compose.
- PostgreSQL 16 (контейнер `postgres:16`).
- Python 3.12 для ML; `httpx==0.28.1` зафиксирован в корневом `requirements.txt` и в `ml/requirements.txt` (ML Docker image собирается из каталога `ml`).
- Go 1.25.0 для бекенда; прямые и транзитивные модули зафиксированы в `backend/go.mod` и `backend/go.sum`.
- Nginx для отдачи фронтенда; Node.js и сборщик фронтенду не нужны.
- Доступ к OpenRouter и API-ключ для режима `ML_MOCK=false`.

## Известные ограничения

- Знания ML ограничены документами в `ml/knowledge-base.zip`; загрузка документов через интерфейс не реализована.
- Чат создаётся в интерфейсе как пустой черновик и сохраняется на бекенде после отправки первого вопроса. Старые чаты загружаются в список истории.
- ML HTTP-слой принимает только `id` и `question`. Бекенд включает недавние сообщения в текст `question`, а не отправляет отдельное структурированное поле истории.
- Источники привязаны к пути файла внутри `knowledge-base.zip`; при переименовании или удалении документа сохранённая ссылка старого сообщения может перестать работать.
- Проверка релевантности выполняется на стороне ML после прежнего вызова внешней LLM. Она не меняет содержимое запроса к модели; порог embeddings можно подстроить через `ML_SOURCE_MIN_COSINE`.
- ML извлекает текст из TXT, Markdown и DOCX; текстовые документы при скачивании преобразуются в DOCX, а исходный DOCX сохраняется без изменений. PDF не входит в список форматов, загружаемых текущим парсером базы знаний.
- Учёт чатов привязан к cookie браузера `client_id`; очистка cookie создаст для браузера новую область чатов.
- Бекенд автоматически удаляет неактивные чаты старше 24 часов; это значение задано в конфигурации бекенда по умолчанию.
